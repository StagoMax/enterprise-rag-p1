# 企业工作流 RAG 需求文档

## 1. 产品范围

### 1.1 产品目标

为企业用户提供一个可审计的问答入口：它能够解释已授权的企业专属知识，针对实时或精确事实调用权威工具，并在无证据或无权限时可靠拒答。

### 1.2 P1 范围

- 一个人工选定的试点知识领域。
- TechQA 单领域子集作为 RAG 代理语料。
- BIRD 的 1-2 个 schema 作为只读 SQL 工具数据。
- 120 条固定金标问题和按业务分类映射的测试角色。
- 多格式解析作为 P1.1 阶段门槛，在 Graph RAG 前完成。

### 1.3 非目标

- 不建设覆盖全公司的知识库。
- 不导入邮件、即时通信、全量工单、全量公开网页或通用百科。
- 不允许模型直接修改业务系统或执行审批。
- 不在 P1 建设多租户、多地域容灾、百万级以上真实文档集群或全自动实体知识图谱。

## 2. 角色

| 角色 | 责任 |
|---|---|
| 普通用户 | 查询其被授权的企业知识和业务事实，查看引用，提交反馈 |
| 数据所有者 | 指定分类、允许角色、版本、生效状态和保留期限 |
| 知识管理员 | 执行导入、审核解析失败、发布/回滚索引版本 |
| 平台管理员 | 管理服务、模型、连接器、可观测性和事故处理 |
| 安全审计员 | 查看权限策略、访问记录、拒答和越权拦截记录 |

## 3. 功能需求

### FR-01 身份与会话

系统必须通过 OIDC/OAuth2 获取用户身份和角色。P1 可以使用测试身份提供方，但不得允许客户端自行声明角色。

### FR-02 文档导入与解析

系统必须接收 PDF、DOCX、PPTX、XLSX、HTML 和纯文本的原始资源，并保存原始文件、解析产物、校验和、解析器版本和失败原因。P1 实际验收至少覆盖 PDF、DOCX、HTML 和扫描 PDF 样本。

### FR-03 元数据与版本

每份可发布资源必须具备资源 ID、来源、业务分类、所有者、生效状态、版本、敏感级别和允许角色。缺少这些字段的资源不得发布到生产索引。

### FR-04 权限策略

系统必须支持“业务分类 -> 默认角色”映射，以及文档/分块级例外策略。每次访问必须记录策略版本和最终允许/拒绝决策。

### FR-05 切块与引用锚点

系统必须按文档结构切块，保留文档标题、章节路径、页码或可定位锚点。分块不得跨越不同源文档或不同权限边界。

### FR-06 混合检索

对 RAG 请求，系统必须在 ACL 过滤后执行关键词检索和向量检索，融合结果后进行重排。结果应返回相关性分数、资源版本和引用锚点供后续生成使用。

### FR-07 Graph RAG（P2）

P2 必须支持文档、章节、分块、引用和版本关系的有限图遍历。图扩展只能使用已授权节点，且必须能够说明扩展路径。P1 不启用图遍历，只保留支撑引用的文档结构元数据。

### FR-08 请求路由

系统必须将每个请求分类为 `rag`、`exact_search`、`tool` 或 `handoff_or_refuse`，并输出路由理由和置信度。低置信度问题必须进入澄清或拒答，而不是随机选择工具。

### FR-09 RAG 回答

系统必须只使用检索到的已授权证据回答企业事实。每个关键结论均应至少附一个可定位的来源；证据不足时必须说明无法确认。

### FR-10 精确检索

对于编号、名称、版本、错误码、条款号等问题，系统必须支持字段过滤和关键词精确检索，不得只依赖向量相似度。

### FR-11 SQL 工具调用

对于 BIRD schema 中的结构化问题，系统必须经只读 SQL 工具返回结果。SQL 必须通过 AST 校验，只允许白名单 schema 的 `SELECT` 查询，并限制执行时间、扫描范围和返回行数。

### FR-12 拒答与转交

无权限、无可用证据、需要执行动作、超出当前数据域或工具失败时，系统必须拒答或提供权威系统/人工流程的转交建议。不得虚构企业数据或文档。

### FR-13 审计与反馈

系统必须记录请求身份、时间、路由、索引版本、权限决策、检索引用、工具调用摘要、模型版本、延迟和反馈。用户可以将结果标为有用、无用、引用错误或权限问题。

### FR-14 索引发布与回滚

系统必须支持导入预览、质量检查、原子发布、失效、撤权和回滚。资源失效后，其关键词、向量和图索引应在约定时限内不可检索。

### FR-15 评测

系统必须能运行固定金标集，输出路由、检索、引用、拒答、权限和工具调用的分项指标，并保留每次评测的版本信息。

## 4. 非功能需求

| 编号 | 需求 | P1 验收目标 |
|---|---|---|
| NFR-01 | 权限隔离 | 对权限金标集，未授权文档/分块零召回、零引用、零工具越权 |
| NFR-02 | 路由质量 | 120 条金标问题的总体路由正确率不低于 90%，`tool` 与拒答类不低于 95% |
| NFR-03 | 检索质量 | RAG 与精确检索金标题的证据 Recall@3 不低于 85% |
| NFR-04 | 引用质量 | Top-1 来源正确率不低于 95%，且可定位到版本与章节/页码 |
| NFR-05 | 拒答质量 | 证据不足和越权金标题的正确拒答率不低于 90% |
| NFR-06 | SQL 正确性 | BIRD 试点题的执行正确率不低于 85%，所有不合规 SQL 均被拦截 |
| NFR-07 | 响应性能 | 在约定 P1 硬件和并发下，RAG 请求端到端 P95 不高于 6 秒；工具请求不含外部系统等待的 P95 不高于 4 秒 |
| NFR-08 | 可追溯性 | 100% 成功回答具备 `trace_id`；100% RAG/工具回答记录来源版本 |
| NFR-09 | 更新时效 | 资源撤权或失效后，相关索引在 15 分钟内不可被检索 |
| NFR-10 | 可恢复性 | 索引发布失败可回滚至上一个可用版本；原始文件和元数据可重建索引 |

阈值是 P1 初始门槛。具体硬件、模型、并发和外部 API 依赖在测试计划中冻结后，性能指标方可作为正式验收依据。

## 5. 数据需求

### 5.1 P1 数据清单

| 数据 | 规模 | 归属 | 是否进入 RAG | 目的 |
|---|---|---|---|---|
| TechQA WebSphere 文档 | 200 篇 | 公开代理数据 | 是 | 企业专属技术知识解释与混合检索 |
| BIRD `financial` schema | 8 表、32 题 | 公开代理数据 | 否 | SQL 路由、安全和结果引用 |
| 多格式测试包（P1.1） | 50-100 页 | 项目团队维护 | 默认否 | PDF/Office/HTML/OCR、版面和锚点验证 |
| 金标问题集 | 120 条 | 项目团队维护 | 否 | 60 RAG、20 精确、20 工具、10 越权、10 无证据 |

### 5.2 数据准入条件

- 数据所有者、分类、授权角色、版本和生效状态完整。
- 数据集许可证和再分发条件已经审查。
- 无法处理的个人信息、密钥、凭证或未获授权内容已经排除或脱敏。
- 每个资源具有稳定的来源 URI 或资源 ID，可支持删除和更新。

## 6. 接口需求

### 6.1 查询接口

输入包括问题、用户身份、可选数据域、会话 ID 和请求时间。输出包括回答、路由、引用列表、工具来源摘要、拒答原因、反馈 ID 和 `trace_id`。

### 6.2 导入接口

输入包括文件或来源 URI、元数据、权限策略和发布意图。输出包括解析状态、质量告警、待发布索引版本和失败详情。

### 6.3 评测接口

输入包括金标集版本、模型/索引版本和执行配置。输出包括总体及分路由指标、逐题证据、失败样例和与基线的差异。

## 7. 验收场景

1. `engineering` 用户询问 TechQA 文档中的流程性问题，系统路由至 RAG，返回依据文档章节的回答和引用。
2. 用户询问 BIRD 数据库中的聚合数值，系统路由至 SQL 工具，返回数值、查询时间和字段口径，不引用向量库内容。
3. 用户按错误码或版本号定位知识，系统路由至精确检索，返回匹配的当前版本内容。
4. `operations` 用户请求 `engineering` 专属资源，系统在检索前拒绝；审计中无该资源的召回或正文泄露。
5. 用户询问数据域外或证据不足的企业事实，系统明确拒答，不以通用模型知识伪造答案。
6. 管理员撤销一份已发布文档，15 分钟后任何角色均不能通过关键词、向量或图关系检索到该文档分块。
7. 同一金标集在模型或索引版本升级后自动运行，并对低于基线的路由、引用或权限指标阻断发布。

## 8. 发布门槛与后续扩展

P1 只有在第 4 节全部阈值达标、关键安全场景通过且存在可复现的运行手册后，才能进入 P2。P2 每次只增加一种能力或一个数据域，例如先增加 FinQA 的报告/表格分流，再增加 MultiDoc2Dial 的跨文档图关系。不得以“数据越多越好”为理由跳过阶段验收。

当前执行结果中，路由、Recall@3、拒答、权限隔离和工具回答已达到门槛；Top-1 引用为 87.5%，低于 95%。因此 FR-15 的评测闭环已实现，但 P1 发布验收尚未通过，P2 保持阻断。
