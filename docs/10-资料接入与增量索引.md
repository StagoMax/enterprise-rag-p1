# 资料接入与增量索引

## 1. 目标与边界

资料接入已经从“扫描目录并替换整个 SQLite”升级为独立的 Ingestion Gateway。调用方可以来自审阅
面板、HTTP API、CLI、企业微信连接器、对象存储事件或未来的批处理任务；所有入口最终调用同一个
`IncrementalIngestionService`，不会把传输协议写进分块、抽取或索引逻辑。

这仍然是记忆基础设施，不属于 Agent Loop：导入结果只进入 SAG 查询投影，不写 prompt，不自动生成
回答，也不改变当前会话上下文。

## 2. 领域模型

```text
SourceAsset（稳定资料身份）
└── SourceVersion（不可变版本）
    └── Source / EvidenceUnit / Event / Entity（可重建索引事实）

SourceAssetProjection
└── active_version_id（当前有效版本，可原子切换）
```

- `SourceAsset` 由 `namespace + source_key` 稳定定位；调用方也可以保存接口返回的 `asset_id`。
- `SourceVersion` 按正文、标题和业务元数据生成版本指纹，只追加，不更新、不删除。
- 修改资料时，系统重新解析这一份文档；其他资料的块、事件、实体和向量全部复用。
- 旧版本的索引事实保留，但所有向量、实体、FTS 和 SQL 超边路径都只读取活动版本。
- 相同内容重复上传返回 `unchanged`，不会重复调用 DeepSeek 或重新生成向量。
- 相同正文但元数据变化会形成新版本，同时复用正文的派生索引。

SQLite 触发器禁止修改或删除 `source_assets` 和 `source_versions`。当前版本映射是可重建投影，因此允许
原子切换。整个“写版本、写派生索引、切换活动版本、更新索引代次”在一个事务内完成；失败时当前查询
索引保持不变。

## 3. 增量与全量等价

索引保存完整 Pipeline Contract：解析器、分块版本与参数、抽取器、抽取模型、嵌入模型和维度。增量
请求与当前索引契约不一致时会拒绝发布，并要求执行全量重建，避免一个活动索引混入不兼容向量。

在同一契约、确定性抽取结果和相同源资料集合下，必须满足：

```text
Incremental(Current, Delta).active_projection
== FullBuild(Current Sources).active_projection
```

自动化测试会比较活动 Event ID、Event 文本、Evidence 原文和活动统计。全量构建也会读取资料账本中
当前活动的上传文件，因此以后再次运行 `build` 不会丢失 API/界面接入的资料；历史版本账本会复制到
新的暂存库，再随查询投影一起原子发布。

## 4. HTTP API

服务启动后，OpenAPI 文档位于 `http://127.0.0.1:8765/docs`。

### 4.1 上传文件

```powershell
curl.exe -X POST http://127.0.0.1:8765/api/ingestions/upload `
  -F "file=@J:\Docs\publishing-policy.docx" `
  -F "source_key=handbook/publishing-policy" `
  -F "namespace=enterprise_knowledge" `
  -F "title=内容发布规范" `
  -F 'metadata_json={"department":"content","classification":"internal"}'
```

第一次调用返回稳定的 `asset_id` 和版本 1。更新时可以继续传相同 `source_key + namespace`，也可以传回
`asset_id`：

```powershell
curl.exe -X POST http://127.0.0.1:8765/api/ingestions/upload `
  -F "file=@J:\Docs\publishing-policy-v2.docx" `
  -F "asset_id=ast_xxxxxxxxxxxxxxxxxxxxxxxx"
```

### 4.2 直接导入结构化文本

适用于企业微信消息归档、CMS、数据库同步器等不需要浏览器上传的调用方：

```http
POST /api/ingestions/text
Content-Type: application/json

{
  "content": "# 售后规则\n\n退款申请应在七个工作日内审核。",
  "filename": "refund-policy.md",
  "source_key": "policy/refund",
  "namespace": "enterprise_knowledge",
  "title": "退款规则",
  "metadata": {
    "department": "customer_service",
    "source_system": "cms"
  }
}
```

### 4.3 查看当前资料

```http
GET /api/sources
```

返回每个活动 `SourceAsset` 的当前版本、来源键、数据域、文件位置、业务元数据和证据块数量。

## 5. CLI

```powershell
.venv\Scripts\python.exe -m enterprise_sag ingest J:\Docs\policy.docx `
  --source-key handbook/policy `
  --namespace enterprise_knowledge `
  --title "企业制度" `
  --metadata-json '{"department":"hr"}'

.venv\Scripts\python.exe -m enterprise_sag sources
```

CLI、HTTP 和面板返回相同的 `IngestionResult`。默认正式配置继续使用 DeepSeek 抽取与 Nemotron 嵌入；
测试环境可以显式使用 `--extractor deterministic --embedding-backend hashing`。

## 6. 面板操作

打开 `http://127.0.0.1:8765`，展开左侧“新增资料（增量）”：

1. 选择支持的文档；
2. 设置标题、数据域和可选稳定来源键；
3. 在高级区域设置 Asset ID 或 JSON 元数据；
4. 发布成功后从“当前资料”查看版本；
5. 点“更新此资料”自动带入稳定身份，再选择新版文件。

支持 DOCX、PDF、PPTX、XLSX、HTML、Markdown 和 TXT。文件名会去除路径部分并校验后缀，默认最大
100 MiB；上传内容保存到 `data/sag_memory/assets/<asset_id>/<version_id>/`，该目录已被 `.gitignore`
排除。
