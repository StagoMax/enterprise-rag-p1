# 企业工作流大规模 RAG 规划文档

## 1. 背景与目标

本项目建设面向企业工作流的检索增强生成能力。它不是把企业全部数据导入向量库，而是将用户问题路由到合适的权威来源：企业专属知识走 RAG，精确且动态的事实走 SQL、业务 API 或关键词检索，执行性请求走工作流工具。

首要目标是以小规模、可控语料跑通从身份鉴别到可追溯回答的闭环，再逐步扩大数据域、数据量和并发规模。任何扩容均以已完成的质量、安全和运维验收为前提。

## 2. 基本原则

1. 企业专属优先：只索引模型通常不知道、企业内部才有且需要依据的知识。
2. 权威源优先：交易数据、实时状态和唯一事实始终从系统记录源读取，RAG 不复制其权威性。
3. 最小闭环优先：先覆盖一个领域、少量角色和少量问题类型，不以接入数据总量作为阶段目标。
4. 权限先于召回：在关键词、向量、图遍历和工具调用前完成权限约束，分块继承源文档权限。
5. 可引用、可拒答：回答必须能引用已授权证据；证据不足、无权限或路由不确定时拒答或引导至权威系统。
6. 版本可追溯：每个回答可定位至文档版本、分块、索引版本和所调用的工具结果。

## 3. 纳入与排除范围

### 3.1 可进入 RAG 的内容

- 已发布且有责任人的内部 SOP、操作手册、产品配置说明、架构文档和项目决策记录。
- 已审核的 FAQ、已结案案例、复盘报告和业务术语说明。
- 有版本和生效状态的制度、规范和静态报告的解释性正文。
- 数据字典、指标口径、字段定义和数据血缘说明。

### 3.2 不进入 RAG 主语料的内容

- 通用常识、百科、基础编程或办公知识，以及全量公开网页语料。
- 实时或精确业务事实，例如订单、库存、余额、审批状态、人员在职状态和当前配置。
- 业务系统中的结构化明细行、账户记录、操作日志和执行指令。
- 无责任人、无版本、未审核或无法确认生效状态的文档。
- 原始通信流。通信内容只有在被审核并沉淀为知识或决策记录后才可以入库。

### 3.3 混合处理的内容

- 制度、合同和条款：可做语义定位，但最终结论须基于当前生效版本的精确条款检索和原文引用。
- 财务报告：叙述性内容可进入 RAG；金额、期间和指标由数仓或表格查询返回。
- 工单：已审核的结案方案可沉淀至 RAG；进行中的状态、负责人和 SLA 从工单系统读取。

## 4. 第一阶段：最小可行闭环

### 4.1 目标

验证以下闭环，而非验证大规模吞吐：

```text
身份与角色 -> 问题路由 -> 权限过滤 -> RAG / SQL 查询 -> 带引用回答 -> 审计与反馈
```

### 4.2 数据范围

| 用途 | 数据集与范围 | 处理方式 |
|---|---|---|
| 企业专属知识代理语料 | TechQA WebSphere 子集，实际 200 篇文档 | 进入 RAG，按文档和段落建立混合检索索引 |
| 结构化工具调用 | BIRD `financial` schema，实际 8 表、32 题 | 仅通过只读 SQL 工具访问，不写入向量库 |
| 多格式解析验证 | P1.1 建立 50-100 页受控测试包 | 不进入当前索引；验证 PDF/Office/HTML/扫描件解析和引用定位 |

TechQA 仅作为内部技术知识的公开代理语料。第一阶段不得引入全量公开语料、邮件、MS MARCO、BEIR 或其他大规模基准语料。

### 4.3 问题与角色范围

- 三个测试身份：`engineering`、`operations`、`restricted`，另设知识管理员和安全审计员。
- 五类问题：RAG、精确检索、结构化工具、无权限和无证据。
- 已建立 120 条唯一金标问题：60 条 RAG、20 条精确检索、20 条工具、10 条无权限、10 条无证据。

### 4.4 阶段交付物

- 可重复执行的数据导入、解析、切块、索引和版本发布流程。
- 带角色模拟的检索与问答 API 或内部页面。
- RAG、SQL、拒答三路路由及完整审计记录。
- 文档/分块/工具结果级引用。
- 基线评测报告、错误样例集和扩容建议。

### 4.5 当前执行状态

P1/P2 闭环和自动化评测已经运行。P3 又将同一公开代理语料扩展到 TechQA 全量 28,481 篇、147,358 个分块和 7,600 条显式引用关系，并完成 Milvus 持久化版本、断点续传、alias 发布和服务重启挂载。严格 Top-3 评测中，基础 Recall@3 为 65%，Top-1 为 62.5%，仍低于 85%/95% 门槛。因此当前状态是“P3 全量规模实验完成、生产放行阻断”。详见 `docs/05-P2执行与验收报告.md` 和 `docs/07-P3执行与验收报告.md`。

## 5. 分阶段路线图

| 阶段 | 范围 | 进入条件 | 退出条件 |
|---|---|---|---|
| P0：准备 | 明确领域、数据所有者、分类和金标题 | 已选定单一试点领域 | 数据清单、权限映射和验收题完成 |
| P1：闭环 | TechQA 200 篇、BIRD financial、120 题；不启用图遍历 | P0 完成 | 路由、引用、权限和评测指标达标 |
| P1.1：多格式准入 | PDF、DOCX、PPTX、XLSX、HTML、扫描 PDF 测试包 | 检索闭环稳定 | 解析、锚点、表格分流和权限继承通过 |
| P2：中等规模 Graph RAG | TechQA 1,000 篇、307 条显式引用边、180 题 | 用户明确启动实验；不代表 P1 放行 | 跨文档、权限、路径、版本回滚和 P1 回归全部达标 |
| P3：全量规模实验 | TechQA 全量 28,481 篇、Milvus、147,358 分块、7,600 条边 | 用户授权扩展公开代理语料；不代表企业试点 | 持久化索引、断点续传、ACL、图和基础检索门槛达标 |
| P3.1：企业部门试点 | 一个真实部门的已分类、已授权语料和对应工具 | 数据授权、脱敏、源 ACL 和审计方案批准 | 满足试点 SLA、质量、安全和撤权要求 |
| P4：大规模 SAG | 分域分片、增量索引、多租户、高可用 | P3.1 通过容量与稳定性评估 | 规模、成本、恢复和权限审计指标达标 |

本文将用户提出的 SAG 作为“二期大规模检索架构”的代称，不预设其英文展开或具体产品。P4 前必须根据 P3.1 真实部门数据形成 SAG 的正式定义、容量目标和选型决议。

## 6. 第二阶段候选数据

P1 验收后，根据缺失能力按需、分批加入，不一次性全量导入：

P2 第一批复用已审查的 TechQA 包扩至 1,000 篇；P3 继续扩至包内全部 28,481 篇，用于验证 Milvus 持久化索引、断点续传和全量关系图。两者都没有引入新的通用语料。以下数据仍是后续按缺失能力选择的候选项：

| 待验证能力 | 候选数据 | 使用边界 |
|---|---|---|
| 多文档对话与跨文档关系 | MultiDoc2Dial | 作为 Graph RAG 补充语料 |
| 报告文字与表格分流 | FinQA | 文字进 RAG，表格加载到关系库 |
| 精确条款与版本引用 | CUAD | 精确检索和引用链路，不作为纯向量问答 |
| 中文检索与重排 | mMARCO 中文或 MIRACL 中文 | 仅作模型评测与中文能力验证 |
| 规模压测 | MS MARCO passages | 仅作容量、召回和成本压测 |
| 通用检索评估 | BEIR、C-MTEB | 仅作离线评测 |

每批扩容前均须完成许可证、再分发限制、个人信息、数据来源和删除机制审查。

## 7. 数据治理与权限策略

数据集不需要逐条人工标注细粒度权限，但每个原始资源至少需要以下元数据：

```text
资源 ID、来源、业务分类、数据所有者、生效状态、版本、敏感级别、允许角色、保留期限
```

可将业务分类映射为默认角色组，例如“技术文档 -> engineering”。但分类不是完整授权本身；映射关系必须由数据所有者确认、可版本化，并能在文档或分块发生例外时覆盖默认策略。

## 8. 主要风险与控制

| 风险 | 控制措施 |
|---|---|
| 将实时事实误答为知识 | 路由规则、SQL/API 工具、工具结果引用和金标路由测试 |
| 向量检索越权 | 查询前强制 ACL 过滤、权限回归测试和审计告警 |
| 过早堆叠组件 | P1 只使用必要组件，容量组件仅在阶段门槛后引入 |
| 文档过期或互相矛盾 | 版本、生效状态、所有者、失效策略和索引回滚 |
| 公开数据不适合作生产 | 公开数据只做闭环验证；生产必须接入已授权内部语料 |

## 9. 组织与决策

- 业务负责人：定义试点问题、验收答案和知识边界。
- 数据所有者：确认数据分类、角色映射、更新和失效规则。
- 平台团队：实现解析、检索、工具调用、审计和运行保障。
- 安全与合规：批准身份接入、数据隔离、日志留存和数据集许可。
- 评测负责人：维护金标集，定期复核质量、越权和拒答案例。
