# P3 基础检索金标复核

## 范围与方法

审查范围是 P3 的 80 条基础检索金标：60 条普通 RAG 问答和 20 条按文档 ID 的精确查找。复核没有改写任何金标，也没有修改索引或排序。

对每一条金标，复核了目标文档是否存在、是否为 active、是否对题目角色可见；检查了规范化标题和正文的完全重复；用全文 TF-IDF 找出近重复候选；并在 P3 发布索引上重放了 90 个候选和严格的前三个不同文档。

## 总体结果

| 检查 | 结果 |
|---|---:|
| 金标行数 | 80 |
| 金标文档存在、active 且角色可见 | 80 / 80 |
| 唯一金标文档数 | 59 |
| 规范化正文完全重复 | 0 条 |
| 规范化标题完全重复的金标行 | 2 条（同一金标 `swg21998452`） |
| 金标进入前 90 候选 | 77 / 80 |
| 金标进入前 20 个不同文档 | 73 / 80 |
| 金标进入严格 Top-3 | 52 / 80 |

80 条中有 18 个 source id 被不同题目重复使用；60 条普通 RAG 中有 54 个唯一 source id。重复使用不必然是错误，但说明该切片不是 80 个完全独立的文档主题。

## 已确认的问题

| 金标 | 结论 | 证据与建议 |
|---|---|---|
| `rag-005` | 非唯一金标 | 题目没有给出 CVE，`swg21998452` 与 `swg22003256`、`swg22009455`、`swg21979065`、`swg22007664` 都是相同 IIB/WMB Hypervisor Red Hat 安全公告家族。当前 Top-3 已返回其中 3 篇，却因不是指定 id 被判错。应把这 5 篇定义为等价证据组。|
| `rag-019` | 金标错配 | 题目是 Portal 8.5 `INSTCONFFAILED` 且无日志；目标 `swg1PI37248` 是 WebSphere 的 PFBC 属性文件问题，正文不包含 Portal、`INSTCONFFAILED` 或题目错误语境。需要重新寻找原始正确文档。|
| `rag-040` | 金标错配 | 与 `rag-019` 是同一目标文档、同一 Portal 安装问题的变体；同样不应绑定到 `swg1PI37248`。|
| `rag-027` | 金标错配 | 题目是 Decision Center 的 `ClassCastException`，目标 `swg21268440` 是 WebSphere Session Manager 的 `NotSerializableException`，正文不包含 `ClassCastException` 或 Decision Center。需要重新标注。|
| `rag-046` | 金标错配 | 题目问 DataPower 固件降级；目标 `swg21244384` 只说明 `reinitialize` 如何重配设备，正文不含 downgrade/firmware，答案也没有给出降级方法。需要重新标注或将题目改为重初始化。|
| `rag-052` | 过时且与语料矛盾 | 目标答案称 8.5.5.x 只能使用 JDK 7、应升级至 V9；但语料内 `swg24043474` 与 `swg1PI73197` 直接说明 8.5.5.9 及以后可通过 PI73197 支持 Java 8，并已占当前 Top-2。应把这两个 APAR 设为金标并更新答案。|

| 金标 | 原因 | 建议 |

## 对评测结论的影响

金标问题是真实存在的：`rag-005` 会把已经给出等价公告的结果判错，`rag-052` 会把语料中更直接且更新的答案判错。

但这不是全部原因。除去上述问题，仍有大量金标已在前 20 候选中却未进入前三，例如 SSL mutual authentication、MQ 2035、ulimit、DataPower SHA-2、SCA destinations、CCDT/XA 与 TLS 1.2 等。因此不能只改金标，也不能降低 85% Recall@3 / 95% Top-1 门槛；仍需针对 IBM 技术问答训练或选择领域排序器。

推荐顺序：先修复已确认的 6 条标注（其中 `rag-019` 与 `rag-040` 分别计数），再让领域专家确认 `rag-054`；随后用修订后的集合重跑 P3。评测中应支持“证据组”而不是只接受单一 `source_id`，但仅适用于明确的公告/修复包同族文档，不能泛化为任意相似文档。
